Como usar o sistema

Orientações rápidas para navegar pelos módulos da demonstração.

Voltar à visão geral
Este é um projeto de demonstração, não um sistema clínico validado. Não registre dados reais nem use as informações exibidas para orientar decisões de atendimento.

Seu perfil e os módulos

O menu lateral e os atalhos da visão geral mostram os módulos permitidos para o setor da conta conectada. Se um recurso não aparecer, solicite ao administrador que revise o perfil de acesso.

Fluxo de atendimento

  • Atendimento cadastra a chegada do paciente.
  • Triagem registra sintomas e classificação de risco.
  • Médico registra consulta, diagnóstico e encaminhamento.
  • Medicação e alta concluem as etapas correspondentes.

Classificação de risco

As cores são usadas pelo fluxo de demonstração para identificar prioridade. A classificação exibida não substitui avaliação profissional, protocolos oficiais ou julgamento clínico.

Tema e navegação

Use o botão de tema no menu lateral para alternar entre a aparência escura e a clara. A preferência fica salva neste navegador. Em telas pequenas, abra o menu pelo botão no topo.

O que faz o back-end

O back-end é o servidor da aplicação. Ele recebe as solicitações do site, valida os dados, verifica as permissões e devolve respostas para atualizar as telas. Neste projeto, ele é feito em Node.js com Express, no arquivo backend/server.js.

O navegador conversa com o servidor por uma API HTTP que troca dados em JSON. Por exemplo, ao entrar, o site envia as credenciais para /login; ao consultar um perfil, solicita os dados ao servidor, que confere se a conta pode acessá-los.

Login e permissões

  • /login autentica contas comuns e /login/admin autentica administradores.
  • Após o login, o servidor devolve um token de sessão; o site o envia nas próximas solicitações.
  • O servidor verifica o token e as permissões em cada operação protegida. A interface esconder um botão, por si só, não concede nem bloqueia acesso.
  • Senhas novas são armazenadas com hash; senhas antigas em texto puro são atualizadas após um login bem-sucedido. Em produção, use credenciais fortes e únicas e não publique contas de demonstração.

Onde os dados ficam

Atualmente, os dados da aplicação são gravados em backend/db.json (ou no caminho definido por BAYMAX_DB_FILE). Isso é conveniente para desenvolvimento, mas não é um banco de dados gerenciado: o arquivo pode ser perdido em reinícios ou novos deploys se o serviço não tiver armazenamento persistente.

Antes de publicar no Render, configure um disco persistente e a variável BAYMAX_DB_FILE para apontar para ele, ou migre os dados para um banco gerenciado. Planeje também backups e restauração. Não use dados reais de pacientes nesta demonstração.

Executar e publicar

  • O comando de inicialização local é npm start; o servidor usa a porta fornecida pelo ambiente, como o Render.
  • Configure SESSION_SECRET como segredo nas variáveis de ambiente da hospedagem. Use um valor aleatório forte com pelo menos 32 caracteres e não o inclua no código.
  • Antes de publicar alterações, execute npm test e confira os logs do serviço se a inicialização ou alguma solicitação falhar.
  • Este projeto é uma demonstração e não foi validado para uso clínico ou para armazenar informações pessoais reais.
